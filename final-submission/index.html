The Self-Healing Scraper Studio Architecture

OpenRouter lists 500+ AI models across dozens of providers. Capturing this volatile, dynamic dataset required building an automated, self-healing pipeline using Bright Data Scraper Studio. Here is the verified technical progression from DOM scraper failure to API discovery.

1

First Attempt — Direct Webpage Scraping (openrouter.ai/models)

Initial AI scraper built targeting the rendered web table. Captured only 15 models due to client-side infinite scroll & lazy loading.

15 Records
2

Self-Healing Attempt #1 — bdata scraper heal

Dispatched instruction: "Wait for elements and scroll down to load infinite list". Scraper regenerated selector rules. Result: 15 → 16 models.

16 Records
3

Self-Healing Attempt #2 — Aggressive scroll targeting

Instructed deeper scrolling down DOM. Improved to 18 models, but proved that fighting client-side hydration in HTML was suboptimal.

18 Records
4

Strategic Pivot — Discovering OpenRouter Public API

Identified underlying JSON endpoint (openrouter.ai/api/v1/models). Pointed Bright Data Scraper Studio directly at the API payload.

421 Records
5

Final Optimization — Modality Parameter Query

Discovered default API excludes multimodal models. Appended ?output_modalities=all. Landed at full 558 model catalogue.

558 Records (100%)
